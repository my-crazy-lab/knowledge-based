## Database

- [Thiết kế Physical Schema chịu tải cao](./1.0.0/c2gn4i/README.md)
- Sharding kiến trúc Horizontal Scaling	
    - PostgreSQL: pg_shard, Citus
    - MongoDB: shard key, zone
    - Định nghĩa tiêu chí chọn shard key tốt (low cardinality vs high skew)	
    - Đảm bảo khả năng scale out, giảm bottleneck khi 1 node vượt quá khả năng chịu tải
- Tối ưu transaction & concurrency control
    - PostgreSQL: SERIALIZABLE vs REPEATABLE READ
    - Deadlock simulation
    - Advisory locking vs pessimistic locking
    - Xử lý conflict, đảm bảo tính toàn vẹn dữ liệu khi concurrent transactions tăng cao
- Replication & High Availability Design
    - Triển khai replica cluster (1 primary - n replica)
    - Test failover tự động- Monitor replication lag với pg_stat_replication, mongostat	
    - Tăng độ sẵn sàng (HA), hỗ trợ scale đọc, bảo vệ production khi node hỏng
- Write-heavy vs Read-heavy Load Simulation
    - Dùng pgbench, sysbench, hoặc custom load tool
    - Benchmark Read QPS vs Write TPS
    - Tối ưu bằng index, cache, queue, batch write	
    - Phân tích hành vi hệ thống dưới các dạng tải, đưa ra chiến lược phân phối load
- Hybrid: SQL + NoSQL trong cùng hệ thống
    - PostgreSQL (OLTP) cho transactional
    - MongoDB/Redis cho content/document cache
    - Xây bridge bằng app layer hoặc ETL (CDC)	
    - Thiết kế kiến trúc polyglot persistence – chọn đúng DB cho đúng use case
- Zero-Downtime Schema Migration Strategy
    - Flyway/Liquibase versioning
    - Add column → backfill → swap
    - Rollback design, dark launch kiểm thử	
    - Là kỹ năng bắt buộc khi deploy DB ở môi trường production với downtime bằng 0
- Audit Logging + Change Data Capture (CDC)
    - PostgreSQL Logical Replication
    - MongoDB Oplog tailing
    - Debezium Kafka connector
    - Build event-sourcing for DB events	
    - Hỗ trợ audit, phân tích dữ liệu theo thời gian, hoặc xây hệ thống realtime downstream từ dữ liệu DB
- Schema Evolution trong Microservices
    - Chia DB theo bounded context
    - Event outbox pattern
    - DB backward compatibility + integration tests	
    - Giải quyết bài toán DB chia nhỏ (microservices) nhưng vẫn đảm bảo tính nhất quán và forward-compatibility
- Thiết kế chiến lược backup & disaster recovery
    - Point-in-time recovery (PITR)
    - Restore test automation
    - Tính toán RPO/RTO	
    - Đảm bảo không mất dữ liệu khi thảm họa (kỹ thuật hay con người), critical ở tầm architect
- So sánh CAP: MongoDB vs PostgreSQL trong môi trường production
    - Viết 2 use-case yêu cầu độ nhất quán khác nhau
    - Thử partition tolerance, replication inconsistency
    - Kết luận thiết kế	
    - Áp dụng tư duy kiến trúc hệ thống phân tán thực tế – hiểu rõ giới hạn từng hệ quản trị
- Tích hợp Redis làm write-through + fallback cache layer
    - Viết code logic fallback từ Redis → DB
    - Invalidate theo TTL hoặc pub/sub
    - Đo hiệu quả với latency & hit ratio	
    - Tăng tốc hệ thống backend, đảm bảo graceful degradation khi cache lỗi
- Indexing Strategy & Query Plan Optimization
    - Phân tích query execution plan (PostgreSQL `EXPLAIN ANALYZE`, MongoDB `explain()`).
    - Tối ưu composite index, covering index, partial index.
- Multi-region Deployment Strategy
    - Active-active vs Active-passive DB deployments.
    - Latency mitigation & replication lag handling (especially with write-heavy systems).
- Data Lifecycle & Archival Strategy
    - Cold/hot storage strategy.
    - TTL (time-to-live), partitioning cho table quá lớn.
- Security & Compliance
    - Field-level encryption, at-rest vs in-transit encryption.
    - Row-level security (PostgreSQL RLS).
    - GDPR/Data retention strategies.
- Observability & Telemetry cho Database
    - Slow query logs, deadlock monitoring, replication lag alerts.
    - Thống kê database health (pg_stat_activity, Mongo Atlas metrics...).
- Distributed Transactions / Sagas / Eventual Consistency
    - Nếu bạn dùng microservices, thì nên hiểu rõ:
        - Sagas (choreography vs orchestration).
        - Outbox Pattern + Relay + Debezium.
        - Idempotency Key Handling.
- Schema Versioning Tooling
    - Liquibase, Flyway, Sqitch – so sánh & lựa chọn phù hợp.
- Cost Optimization (Cloud DB Services)
    - Chi phí read replica, long-term storage, IOPS-based pricing (RDS/Aurora).
    - Tối ưu hóa schema và indexes để tiết kiệm chi phí trên cloud.

## Clean Arch, Patterns

- Dependency Inversion Principle (DIP)	
    - Tạo Interface + các Adapter cụ thể- Dùng IoC Container (Inversify, Spring, NestJS)	Thực hành DIP - nền tảng của Clean Architecture
Repository Pattern	- Tạo 2 backend khác nhau (InMemory vs Postgres)- Repository interface trung gian- Viết unit test độc lập DB	Cho phép mocking dễ dàng, tách business logic khỏi data source
Command Query Responsibility Segregation (CQRS)	- Phân chia handler Read vs Write riêng biệt- Write → DB, Read → cache- Tối ưu scale và read performance	Áp dụng cho hệ thống scale lớn hoặc write-heavy vs read-heavy
Event-driven domain logic (Domain Events)	- Trigger event trong domain (ex: OrderCreated)- Event handler xử lý logging, email, async ops- Dùng Event Bus hoặc simple pub/sub	Tách biệt domain logic + cross-cutting concern
Service Layer vs Application Layer phân biệt rõ	- Viết use case trong Application Layer- Controller gọi UseCase thay vì Business Logic	Thể hiện đúng architecture intentionBusiness logic không dính vào Web/DB/IO
Builder Pattern cho object phức tạp (Report, Invoice...)	- Tạo một report với nhiều config (CSV, PDF...)- Dùng Builder pattern để generate object	Tránh constructor dài, tăng readability
Factory + Strategy Pattern	- Factory: tạo instance của PaymentMethod (PayPal, Stripe)- Strategy: thay đổi logic vận chuyển, giảm giá...	Thực hành lựa chọn động theo runtime behavior
State Pattern (ex: Order Status, Workflow)	- Triển khai Order với state transition (Pending → Paid → Shipped)- Mỗi state có behavior riêng	Tăng khả năng mở rộng logic theo từng trạng thái
Specification Pattern (kiểm tra Rule phức tạp)	- Tách điều kiện (rules) phức tạp thành Specification object- Compose bằng AND, OR, NOT	Dễ dàng test rule, reuse, combine logic
Decorator Pattern	- Decorate handler bằng logging, retry, auth...- Không thay đổi code logic chính	Tách biệt concern theo đúng SOLIDDễ mở rộng mà không sửa lớp chính
Use Case: Viết Service dùng Event-Driven + Clean Architecture	- Build OrderService theo Clean Arch- Event: OrderCreated → Email → Update Inventory- Domain logic chỉ publish Event, không call service trực tiếp	Xây hệ thống loosely coupledReady cho microservices hoặc serverless
